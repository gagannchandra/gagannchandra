### 🔹 [HealthAI — Symptom-Based Disease Prediction](https://github.com/gagannchandra/healthai-disease-prediction) · [Live ↗](https://healthai-disease-prediction.vercel.app/)
> *Python · FastAPI · Scikit-learn · React 19 · Tailwind CSS · Render · Final Year Project (AI Specialization)*

My final year project. The question I kept coming back to: does a soft-voting ensemble actually beat any single classifier on this, or is it just more complexity for marginal gains? Turns out it does help, but not as dramatically as I expected — which was a more interesting result than a clean win would have been.

- **87.84% accuracy** across 141 disease classes and 343 symptom features — soft-voting over Decision Tree, Random Forest, and Naive Bayes; averaging `predict_proba` rather than hard votes made a noticeable difference
- Returns top-3 diagnoses with confidence scores, plus recommended specialist, medications, diet, and precautions
- Voice input via Web Speech API so users aren't stuck typing out symptoms; Recharts comparison chart so you can actually see how the three models differ
- FastAPI + Pydantic v2 backend; ~5.3 ms average response time, ~187 req/sec per core on Render's free tier

### 🔹 [GitHub Repository Health Checker](https://github.com/gagannchandra/github-health-checker) · [Live ↗](https://github-health-checker-ktmb.onrender.com/) · [Demo ↗](https://youtu.be/M27N7L4T-bE)
> *Python · FastAPI · GitHub REST API · NVIDIA LLaMA 3.1 · Uvicorn*

I wanted to see if you could get an LLM to give a useful, structured opinion on a repo's health — not just a vibe check, but something with actual signal. Turns out if you give it the right metrics and a tight prompt, it does pretty well.

- Fires concurrent GitHub API calls to collect stars, forks, open issues, contributor count, last commit date, license, and repo size — no waiting for them one by one
- Sends the data to NVIDIA-hosted **LLaMA 3.1 (8B Instruct)** with a structured prompt; gets back strengths, concerns, overall summary, and a score out of 100
- Auto-assigns a status badge — **Active / Inactive / Needs Review** — based on the score
- Async FastAPI + Uvicorn; dark card-based UI; deployed on Render

### 🔹 [TaskFlow — Team Task Manager](https://github.com/gagannchandra/team-task-manager) · [Live ↗](https://team-task-managerr.up.railway.app)
> *React 19 · Node.js · Express · MongoDB Atlas · JWT · Railway*

Built this to get proper hands-on experience with role-based auth and full-stack deployment — not toy auth, but the kind where different users genuinely can and can't do different things. The monorepo single-service deploy (Express serving the React build directly) took some figuring out but means zero frontend deployment overhead.

- JWT + bcrypt auth; role middleware enforces Admin (full CRUD) vs Member (view & update assigned tasks only) — tested by actually trying to break it
- Kanban board with task status tracking; dashboard with team overview and task breakdown by status
- Mongoose models for User, Project, ProjectMember, and Task; `express-validator` on all inputs
- Single Railway service: root `postinstall` installs both packages; Express serves `frontend/dist/` statically in production

### 🔹 [Shortly — URL Shortener with Analytics](https://github.com/gagannchandra/shortly-url-shortener) · [Live ↗](https://shortly-pxjs.onrender.com/)
> *Python · Flask 3 · MongoDB · PyMongo · Docker · GitHub Actions*

Started as "I wonder how bit.ly works" and turned into a proper two-version project. v1 was Flask + SQLite — got the basics working, learned where the edges were. v2 is the rebuild with everything I wished v1 had: MongoDB with TTL indexes that auto-delete expired links (no cron job needed, which felt like cheating in a good way), rate limiting, security headers, Docker, and a CI pipeline that runs on every push.

- Short codes use `secrets.choice` not `random` — predictable randomness is an actual attack vector, learned that the slightly uncomfortable way
- Link expiry via MongoDB's sparse TTL index — set `expires_at`, MongoDB handles the rest; permanent links just have `null` and the index ignores them
- QR code comes back with every new link as a base64 data URI, no extra request needed; analytics page shows a 14-day click chart with zeros filled in so the chart never has weird gaps
- Clean API envelope: every response is `{data, status}` or `{error, status}` — consistent enough that the frontend never has to guess the shape
- Multi-stage Docker build with a non-root runtime user; Compose brings up the app + MongoDB + an optional Mongo Express UI; GitHub Actions runs the full test suite (with `mongomock`, so no real DB needed in CI)
